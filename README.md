# Software-G

Repositorio de trabajo del equipo para organizar y desarrollar el proyecto de software. Aquí se centralizan el código, la documentación y los acuerdos de colaboración.

## Estado del proyecto

El repositorio se encuentra en una etapa inicial. La estructura para el código y la documentación ya está preparada, pero todavía no hay una aplicación ejecutable ni instrucciones de instalación. Esta sección se actualizará cuando se definan e incorporen la tecnología y las funciones del proyecto.

## Estructura del repositorio

```text
.
├── docs/                 # Documentación del proyecto
├── equipo/               # Perfiles y aportes de integrantes
├── src/                  # Código fuente
├── CONTRIBUTING.md       # Convenciones de ramas, commits y revisión
└── README.md             # Descripción y guía general del repositorio
```

## Colaboración

Los cambios se trabajan en ramas y se integran a `main` mediante Pull Requests:

1. Crea una rama para tu tarea desde `main`. Usa un prefijo según el tipo de cambio, por ejemplo `docs/`, `feat/` o `fix/`.
2. Realiza los cambios y crea commits con el formato `tipo: descripción`, por ejemplo `docs: completar README`.
3. Sube la rama al repositorio y abre un Pull Request con destino a `main`.
4. Solicita la revisión de otro integrante. No se debe aprobar el propio Pull Request.
5. Atiende las observaciones y fusiona el Pull Request cuando haya sido aprobado.

Consulta [CONTRIBUTING.md](CONTRIBUTING.md) para ver las convenciones completas del equipo.
